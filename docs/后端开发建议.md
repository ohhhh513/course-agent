# 课程智能体系统 · 后端开发建议

> 配套阅读：`接口文档.md`（60+ 接口契约）、`数据模型与Mock说明.md`（字段真相源）、`鉴权与会话方案.md`、`后端对接指南.md`（前端对接步骤）。
> 本文解决的是"后端本身怎么搭"：技术栈、架构、库表、关键决策、排期与质量门禁。
> 核心前提：**前端通过 `API.config.mode='http'` 零改动切到真实后端，前提是后端返回的 `data` 字段形状 = `数据模型与Mock说明.md` 对应对象**。

---

## 一、技术栈推荐

### 推荐方案 A：Python + FastAPI（默认推荐）
- **理由**：系统两大重头戏是 **AI 答疑（RAG + 溯源）** 与 **AI 出题（LLM 结构化生成）**，Python 在 LLM/RAG/数据分析生态上最成熟；FastAPI 原生异步、Pydantic 既能做请求校验又能直接当响应契约（response_model），与"字段形状必须=文档"的要求天然契合。
- 组合：`FastAPI` + `SQLModel/SQLAlchemy` + `PostgreSQL` + `pgvector`（RAG 向量）+ `Redis`（JWT 黑名单/缓存）+ `Celery` 或 `BackgroundTasks`（报告生成、素材解析异步）+ `Pydantic`。

### 备选方案 B：Node.js + NestJS
- **理由**：与前端同源（TS），若团队是纯前端背景、希望前后端一套语言，NestJS 的分层（module/controller/service）和 DI 也很规整；AI 部分用厂商 Node SDK 同样可行。
- 组合：`NestJS` + `TypeORM/Prisma` + `PostgreSQL` + `Redis` + `bull`(队列) + `LangChain.js`。

### 不推荐
- 纯 Python Flask / 纯 Express：能跑，但缺内置契约与分层，后期接口膨胀（60+）后易乱。
- Java/Spring：企业稳健，但本系统 AI 占比高、迭代快，起步偏重。

> 结论：**默认选 A（FastAPI）**；若团队 JS 为主则选 B。下文以 A 为例给结构，B 可一一映射。

## 二、架构与分层

```
浏览器 ── HTTP/JSON ──▶ Nginx(反向代理/静态) ──▶ FastAPI 应用
                                   │
                          ┌────────┴─────────┐
                          │  Routers(接口层)   │  ← 严格按 接口文档.md 的 path 落地
                          │  Services(业务)    │  ← 学情统计/LLM/RAG/判题/报告
                          │  Models(SQLAlchemy)│  ← 库表
                          │  Schemas(Pydantic) │  ← 响应契约 = 数据模型文档
                          └────────────────────┘
```

**黄金规则（最重要）**：所有响应统一包裹信封 `{code,message,data,traceId}`；`data` 的形状由 Pydantic `response_model` 强制，必须等于 `数据模型与Mock说明.md` 的对应对象。前端据此零改动。

## 三、推荐项目结构（FastAPI）

```
backend/
├─ app/
│  ├─ main.py                 # 装配路由、CORS、异常处理、envelope
│  ├─ core/
│  │  ├─ config.py           # 读 .env（DB/Redis/JWT_SECRET/LLM_KEY）
│  │  ├─ security.py         # JWT 签发/校验 get_current_user 依赖
│  │  ├─ envelope.py         # 统一响应 + 业务异常 → 信封
│  │  └─ deps.py             # DB Session 依赖
│  ├─ models/                # SQLAlchemy 表：User/Class/Kp/Graph/Resource/
│  │                         #   Practice/Question/Alert/Intervention/Report...
│  ├─ schemas/               # Pydantic：与数据模型文档 1:1 对应
│  ├─ routers/               # auth/student/teacher/graph/ai/practice/
│  │                         #   analysis/question/intervention/report
│  ├─ services/              # analytics(统计) / llm(答疑) / rag(检索) /
│  │                         #   grading(判题) / report(报告) / generator(出题)
│  └─ db/                    # session.py + seed.py（导入 mock/data.js 的 45 键）
├─ tests/
│  ├─ contract/              # 关键：逐接口比对 data 形状 = 文档/mock
│  └─ api/                   # 业务冒烟
├─ alembic/                  # 迁移
├─ requirements.txt
├─ .env.example
└─ README.md
```

> 前端 `api.js` 的 baseURL 用 `/api/v1`，开发期用 Nginx/Vite 把 `/api` 反代到 `backend:8000`，避免跨域。

## 四、关键设计决策

1. **信封与字段一致性是第一优先级**
   - 写中间件/异常处理器，把成功与业务失败都包成 `{code,message,data,traceId}`。
   - 用 `response_model` 锁定 `data` 结构；**加 contract test**：加载 `mock/data.js` 的对应键，对真实接口返回的 `data` 做深比较，形状不符即失败。

2. **鉴权（JWT）**
   - `POST /auth/login` 校验账号密码，签发含 `userId/role` 的 JWT；`GET /auth/profile` 由 JWT 解析身份，**不要**前端重复传 userId。
   - 失效 token 返回 `401` + 统一信封；可选 `POST /auth/logout` 把 jti 进 Redis 黑名单。
   - `User` 字段名严格按 `鉴权与会话方案.md §5`（role/name/org/avatarChar 等），否则顶栏/守卫读不到。

3. **AI 答疑（RAG + 严格溯源）**
   - 课程资料切块入库 `pgvector`，答疑时检索 top-k，连同 `source`/`locator`/`quote` 一并送 LLM。
   - 响应必须含 `content`(HTML) + `citations[{source,locator,quote,kp}]` + `outOfScope`。
   - **严格溯源约束**：检索无命中/超课程范围 → 返回 `outOfScope:true` + 降级文案，不输出推测答案（前端据此展示"转人工"）。
   - 流式为可选增强：`POST /ai/chat/stream`（SSE）替代一次性 `/ai/chat`，前端已预留平滑替换。

4. **AI 出题（结构化生成）**
   - 要求 LLM 输出 JSON，Pydantic 校验后入库；强制回填溯源字段 `kpPath/preKp/postKp/sourceRef{fileId,locator}`（前端以此画知识点定位树）。
   - `POST /question/materials` 上传素材后**异步**解析（BackgroundTasks/Celery），返回 `{fileId,status,progress}` 供轮询。

5. **学情统计（聚合）**
   - 驾驶舱/热力图/掌握矩阵/能力雷达等靠 SQL 聚合；数据量上来后用物化视图或定时预计算，避免每次请求实时算。

6. **异步重任务**
   - `/report/generate`、`/question/materials` 走后台任务；前端目前是同步 mock，可先同步返回占位、后续升级轮询/通知。

7. **种子数据**
   - 把 `mock/data.js` 的 45 个顶层键作为种子导入库，联调即"所见即所得"，也直接喂给 contract test 做 baseline。

## 五、数据库表（与 Mock/数据模型对应，示意）

| 表 | 来源（Mock 键/实体） | 要点 |
| --- | --- | --- |
| users | `teacher`/`student`(User) | userId(PK), role, name, title, dept, classes(JSON) |
| classes | User.classes | classId, name, studentCount |
| courses / chapters / knowledge_points | `course`, GraphNode | kpId, name, category, mastery, difficulty, isKey, hours, pre/post 关系 |
| graph_links | GraphLink | source, target, relation |
| resources | `resources` | resId, type, kp, progress, duration/pages/count |
| practices / practice_sessions / practice_answers | `practiceQuestions`,`practiceReport`,`wrongBook` | 会话、答题、判分、错题本 |
| ai_sessions / ai_messages | `chatHistory`,`chatMessages` | 会话与带 citations 的消息 |
| teacher_students / heatmaps / student_profiles | `students`,`heatmap`,`studentProfile` | 监测看板数据 |
| alerts | `studentAlerts`,`teacherAlerts` | level, status, trigger, trendData |
| questions / question_bank | `generatedQuestions`,`questionBank` | 生成题 + 题库（含溯源字段） |
| interventions / intervention_effects | `interventions`,`interventionEffect` | 干预建议与前后对比 |
| reports / report_sections | `reportList`,`reportDetail` | 报告归档与章节 |

> 百分比用 0–100 数值（非 `"62%"` 字符串）；时间用 ISO 或 `'YYYY-MM-DD HH:mm'`；颜色用 CSS 串——与 `数据模型与Mock说明.md §4` 一致。

## 七、质量门禁（别只靠前端 verify-load.js）

> 重要澄清：`verify-load.js` 只是**前端加载冒烟测试**——它桩掉了 `API`，所以**根本不会真的打到后端**。它验证"前端拆得对"，**不验证后端对不对**。

后端正确性的真正闸门应是：

1. **Contract 测试（核心）**：pytest 逐接口请求真实后端，深比较 `data` 与 `数据模型文档`/`mock/data.js` 形状。任一字段缺失/类型不符即红。
2. **前端浏览器走查**：`API.config.mode='http'`，按 `页面与功能清单.md` 逐视图核对渲染（见对接指南 §4.3 自测清单）。
3. **字段对齐优先**：后端不必一次实现 60+ 接口，但已实现的 `data` 结构必须与文档一致（对接指南 §5 已列 mock 仿真→真实映射）。

## 八、风险与对策

| 风险 | 对策 |
| --- | --- |
| 后端 `data` 形状与文档漂移，前端白屏 | contract test 卡死；PR 必须跑；用 Pydantic response_model 从源头锁形 |
| AI 答疑胡编（无溯源） | RAG 检索前置；命中不足即 `outOfScope` 降级；禁止无引用作答 |
| 学情统计实时算导致慢 | 物化视图/预计算 + 缓存；热点接口加 Redis |
| 跨域/代理配置错，前端一直走 mock | 统一 `/api` 反代；核对 `api.js` baseURL 与 `mode` |
| 账号体系不安全（原型用 localStorage 种子） | 真实用户库 + JWT；`reset-password` 叠验证码/安全问题 |
