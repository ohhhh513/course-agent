# 后端对接指南

> 目标读者：后端开发者。
> 本指南说明如何把前端原型（mock 数据）无缝切换到真实后端，并给出**必须实现的接口优先级清单**、请求/响应/错误码约定、联调步骤与注意事项。

---

## 1. 三步完成对接

### 步骤 1：实现接口并满足契约
按 `接口文档.md` 实现全部接口，确保：
- Base URL 前缀 `/api/v1`（可在 `api.js` 的 `config.baseURL` 调整）。
- 所有响应包裹统一信封（见 §3）。
- 每个接口的 `data` 字段结构 = `数据模型与Mock说明.md` 中对应 Mock 对象（前端零改动依赖此一致性）。

### 步骤 2：开启 http 模式
修改 `assets/js/api.js`：
```js
const config = {
  mode: 'http',          // mock → http
  baseURL: '/api/v1',
  token: 'Bearer <JWT>', // 登录后由前端写入
  latency: [0, 0]
};
```
> 可选：前端在 `Auth.login` 成功后将后端返回的 `token` 存入 `API.config.token` 并写入会话，后续请求自动带 `Authorization` 头。

### 步骤 3：联调验证
启动前端静态服务 + 后端服务，按 `页面与功能清单.md` 逐页走查；建议从 P0 接口开始，逐步扩展。

## 3. 请求 / 响应 / 错误码约定

### 3.1 统一响应信封（所有接口）
```json
{ "code": 0, "message": "success", "data": { }, "traceId": "svc-xxxx" }
```
- `code === 0` 表示成功；前端读取 `data`。
- `code !== 0` 表示业务失败，前端展示 `message`（中文）。

### 3.2 鉴权头
```
Authorization: Bearer <JWT>
```
- 受保护接口缺失 / 失效 token 返回 `401`，建议信封 `code` 用非零（如 401）并在 `message` 说明。
- 身份（userId / role）由后端从 JWT 解析，**请勿依赖**前端在 query/body 重复传 userId。

### 3.3 错误文案
- 登录失败：`账号不存在` / `密码错误，请重试`（前端据此区分提示）。
- 找回密码：`账号不存在` / `新密码至少 6 位`。
- 其他异常：返回可读中文 `message`，前端通过 `Toast` 直接展示，不做二次翻译。

### 3.4 列表分页
列表类接口统一返回：
```json
{ "total": 120, "list": [ ... ] }
```
支持 `page`（从 1 起）、`size`；筛选参数见各接口文档。

### 3.5 内容类型
- `POST/PUT/DELETE` 用 `application/json` body。
- `GET` 参数拼 query。

## 4. 联调方式

### 4.1 本地跨域 / 代理
前端为静态资源，后端为独立服务时，建议：
- 后端开启 CORS（`Access-Control-Allow-Origin` 指向前端域名，`Allow-Headers` 含 `Authorization, Content-Type`）；或
- 用 Nginx / Vite 代理把 `/api` 转发到后端，前端 `baseURL` 设为 `/api/v1`。

### 4.2 启动与走查
```bash
cd course-agent
python3 -m http.server 8080
# 浏览器打开 http://127.0.0.1:8080/  （登录页）
# 用演示账号 student/123456 进学生端；teacher/123456 进教师端
```
对照 `页面与功能清单.md` 逐视图验证数据渲染。

### 4.3 自测 checklist
- [ ] 登录成功写入会话并跳对应端；错误账号/密码有正确提示。
- [ ] 未登录直接访问 `student.html` / `teacher.html` 被守卫跳回登录页。
- [ ] 三图谱、驾驶舱、热力图、学情矩阵正常渲染（无控制台报错）。
- [ ] AI 答疑返回 `content` + `citations`；越界问题返回 `outOfScope` 降级。
- [ ] 练习流程（组卷→作答→判分→报告）闭环。
- [ ] 教师端班级切换后数据随之刷新。
- [ ] 找回密码后可用新密码登录。

## 5. 已知 Mock 仿真逻辑（真实环境由后端实现）

| 能力 | 原型 mock 行为 | 后端应做 |
| --- | --- | --- |
| AI 答疑 | 关键词命中返回预设答案；否则 `outOfScope` 降级 | 大模型 + 课程资料检索，输出带 citations 的答案；超范围按约束降级 |
| AI 出题 | 返回写死样本 `generatedQuestions` | 大模型按素材/知识点生成，并回填 `kpPath/preKp/postKp/sourceRef` |
| 图谱掌握率 | 写死数值 | 由学习行为数据实时统计 |
| 预警 | 写死列表 | 规则/模型实时计算并推送 |
| 练习判分 | 与 `practiceQuestions` 中的 `answer` 比对 | 由题库/判题服务返回 |
| 账号体系 | `localStorage.ca_accounts` 种子演示账号 | 真实用户库 + JWT；`reset-password` 叠加二次校验 |

## 6. 常见问题

**Q：后端已实现，但前端一直走 mock？**
A：确认 `API.config.mode === 'http'`，且 `baseURL` 可达；浏览器控制台 Network 面板查看请求是否发往 `/api/v1`。

**Q：接口返回了数据但页面空白 / 报错？**
A：多为 `data` 字段结构与 `数据模型与Mock说明.md` 不一致（缺字段或数组/对象错位）。按该文档 §3「强依赖字段路径」逐项核对。

**Q：列表接口分页不生效？**
A：确认返回 `{ total, list }` 结构，且分页参数名用 `page`/`size`。

**Q：登录后请求 401？**
A：检查 `Authorization` 头格式为 `Bearer <token>`，token 未过期；前端 `API.config.token` 已在登录后更新。

**Q：需要支持 SSE 流式答疑吗？**
A：非必须。当前前端调用一次性 `POST /ai/chat`；流式为可选增强，对应 `POST /ai/chat/stream`，后续可平滑替换。
