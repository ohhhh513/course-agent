## 二、公共接口契约（并行开发的"宪法"）

所有人**只通过以下契约**协作，禁止跨文件直接改动他人内部实现。契约由 **P1** 在 D4 前冻结并写入本表，此后变更须走 PR + 评审。

### 2.1 全局共享符号（定义于 common.js / auth.js / api.js）
`Router`、`U`、`API`、`MOCK`、`R`、`Modal`、`Toast`、`Charts`、`Theme`、`icon`、`initTopbar`、`Auth`。

- 取数一律走 `API.<module>.<method>(payload)`，**禁止**页面直接读 `MOCK`。
- 切换真实后端：仅改 `API.config.mode = 'http'` + 注入 `API.config.token`，页面零改动。

### 2.2 跨模块调用的公共入口（务必保持签名稳定）
| 调用方 | 被调用方（拥有者） | 契约签名 | 用途 |
| --- | --- | --- | --- |
| `dashboard` / `mastery` | `Chat`（P2·chat.js） | `Chat.render()` | 跳转/内嵌 AI 答疑 |
| `mastery` | `ResourceView`（P3·resource.js） | `ResourceView.render()`、`ResourceView._pendingKp`（字符串，写入待定位知识点名） | 学情页点知识点→定位资源中心 |
| `analysis` | `Monitor`（P4·monitor.js） | `Monitor.openProfile(userId)` | 归因页点学生→打开个体画像抽屉 |

### 2.3 教师端全局状态（定义于 teacher/app.js，P1 拥有）
- `classSel`：班级下拉 DOM；`state = { classId }`：当前班级，所有教师视图经 `state.classId` 取数。
- `ViewFns`：`{ dashboard, monitor, analysis, question, intervention, report }` 每个 `() => Xxx.render()`，班级切换时 `ViewFns[Router.current]()` 重渲染当前视图。
- 所有教师视图的 `render()` 方法名固定为 `Dash/Monitor/Analysis/Question/Intervention/Report` 上的 `render()`（见各 `Router.register` 的 `mount`）。

## 三、5 人分工方案

> 负载以**视图行数 + 逻辑复杂度**估算，学生端整体重于教师端，故学生侧两人、教师侧两人、1 人做架构/集成。

### 👤 P1 · 架构 / 公共底座 / 集成负责人（Tech Lead）
- **拥有**：`common.js`、`auth.js`、`api.js`、`charts.js`、`mock/data.js` 形态维护；学生/教师两端 `app.js` + `start.js`（路由守卫、班级切换、顶栏）；`verify-load.js` 验证框架；跨模块契约锁定；最终集成。
- **阶段职责**：D1–D4 冻结契约、产出可加载骨架；全程负责分支策略、CI 门禁（`node verify-load.js` 必须全绿）、mock→http 切换、最终联调与缺陷归派。
- **关键交付**：`API.config` 切换机制、`verify-load.js` 持续通过、统一代码规范。

### 👤 P2 · 学生端 A（驾驶舱 / 图谱 / 学情 / AI 答疑）
- **文件**：`dashboard.js`、`graph.js`、`mastery.js`、`chat.js`（路由 `ai`）。
- **API**：`stu.dashboard`、`graph`、`stu.mastery/ability/growth/compare`、`ai.*`。
- **公开契约**：`renderDashboard()`（函数）、`GraphView.render()`、`Mastery.render()`、`Chat.render()`。
- **对外依赖**：消费 P3 的 `ResourceView.render()` 与 `ResourceView._pendingKp`。
- **注意**：`chat.js` 体量最大且含 SSE/流式答疑逻辑，优先落地。

### 👤 P3 · 学生端 B（资源 / 练习 / 预警）
- **文件**：`resource.js`、`practice.js`（最大，492 行）、`alerts.js`。
- **API**：`stu.resources`、`practice.*`、`stu.alerts` + `stu.messages`。
- **公开契约**：`ResourceView = { render(), _pendingKp }`、`Practice.render()`、`Alerts.render()`。
- **对外提供**：`ResourceView` 供 P2 的 `mastery` 调用（明确 `_pendingKp` 读写约定）。
- **注意**：`practice.js` 含练习会话/即时判分/错题本等复杂状态机，是本端最高风险文件。

### 👤 P4 · 教师端 A（驾驶舱 / 监测 / 报告）
- **文件**：`dash.js`、`monitor.js`、`report.js`。
- **API**：`tea.dashboard`、`tea.heatmap/students/profile/alerts`、`report.*`。
- **公开契约**：`Dash.render()`、`Monitor.render()`、`Monitor.openProfile(userId)`、`Report.render()`。
- **对外提供**：`Monitor.openProfile` 供 P5 的 `analysis` 调用。

### 👤 P5 · 教师端 B（归因 / 出题 / 干预）
- **文件**：`analysis.js`、`question.js`、`intervention.js`。
- **API**：`analysis.*`、`question.*`、`intervention.*`。
- **公开契约**：`Analysis.render()`、`Question.render()`、`Intervention.render()`。
- **对外依赖**：消费 P4 的 `Monitor.openProfile(userId)`。
- **注意**：`question.js` 含素材上传/异步解析/AI 组卷/批量审核，状态较多。

## 四、协作流程

### 4.1 分支策略（Git）
- `main`：受保护，仅接受通过评审+`verify-load.js` 的 PR。
- 每人一条长期特性分支：`feat/student-a`(P2)、`feat/student-b`(P3)、`feat/teacher-a`(P4)、`feat/teacher-b`(P5)、`feat/platform`(P1)。
- 每日**从 main 拉最新**合并（rebase），避免后期大规模冲突；契约变更走 `feat/platform` 先合 main，再各自 rebase。

### 4.2 接口契约驱动
- 所有取数走 `API.*`；联调前统一用 `mode='mock'`，P1 保证 mock 结构 = `数据模型与Mock说明.md` = 真实接口 `data`。
- 新增字段先提 Issue + 改 `mock/data.js` 与 `接口文档.md`，再写页面，确保后端/前端/mock 三方可追溯。

### 4.3 每日节奏
- 每日 15 分钟站会：昨日进展 / 今日计划 / 阻塞（重点是跨模块契约是否变）。
- 每日下班前各自分支跑 `node verify-load.js`（P1 维护的 CI 脚本），失败当日修复。
- 代码评审：跨模块调用（Chat / ResourceView / Monitor.openProfile）的改动必须双签（调用方+提供方）。

### 4.4 验证与质量门禁
- **自动门禁**：`node verify-load.js` —— 用 `vm` 沙箱拼接全部子文件、桩接 DOM/API，断言 13 路由全部注册、auth 标志置位。每次 PR 必跑。
- **手动验证**：本环境无浏览器，开发者需本地用浏览器打开 `student.html` / `teacher.html` 走查交互（顶栏、班级切换、跨页跳转、AI 答疑、练习判分、报告导出预览）。

### 里程碑
- **M1（D4）**：契约冻结；`student.html`/`teacher.html` 骨架加载、`node verify-load.js` 全绿。
- **M2（D12）**：13 个视图在 mock 数据下均自测通过；跨模块调用（Chat / ResourceView / Monitor.openProfile）打通。
- **M3（D16）**：`API.config.mode='http'` 直连真实后端，主要链路联调通过（驾驶舱、监测、答疑、练习、出题、报告）。
- **M4（D20）**：端到端验收通过，缺陷清零，文档（含本方案）归档，可交付演示。

### 关键依赖与并行度
- P1 的 `app.js`/`start.js` 与契约是**关键路径**，须 D4 完成，否则 P2–P5 无法并行。
- P2↔P3 仅 `ResourceView` 一处耦合；P4↔P5 仅 `Monitor.openProfile` 一处耦合 → 并行度高。
- 教师端轻于学生端，P4/P5 在 D10 前后即可进入联调预演，可支援 P1 做集成验证。

## 七、验收标准（M4 判定）

1. `node verify-load.js` 全绿：学生 7 路由、教师 6 路由全部注册，`__studentAuthed/__teacherAuthed=true`。
2. `API.config.mode='http'` 直连后端，登录→各视图取数→交互（班级切换、答疑、练习判分、出题、报告导出）全链路无控制台报错。
3. 跨模块调用正确：`mastery` 点知识点定位到 `ResourceView`；`analysis` 点学生打开 `Monitor.openProfile` 画像。
4. 三端（学生/教师/公共底座）代码符合 `接口文档.md` 与 `数据模型与Mock说明.md` 字段约定，无页面直接读 `MOCK`。
5. 文档齐备：本方案、接口文档、前端架构文档、页面清单均更新至交付状态。
