# 课程智能体系统 · 后端开发文档

> 适用版本：v1（FastAPI + SQLAlchemy 2.0 + SQLite/Postgres）
> 配套前端：`course-agent/assets`（通过 `API.config.mode='http'` 切换到真实后端，页面零改动）
> 状态：**AI 答疑 / AI 出题 暂缓上线（预留路由，返回 `available:false`），其余端点已全部真实化（读写持久化）。**

---

## 1. 项目定位与范围

本系统为「课程智能体」前端提供后端服务。本轮开发目标：

- **真实化**：除 AI 模块外，所有端点读写真实关系库，数据可持久化、可回写（练习判分 → 掌握度更新 → 预警 → 报告）。
- **零改页面对接**：前端只需把 `assets/js/api.js` 的 `API.config.mode` 从 `'mock'` 改为 `'http'`，后端响应形状与前端 `mock_data.json` 契约一致，页面无需改动。
- **AI 暂缓**：`POST /ai/chat` 与 `POST /question/gen` 保留路由，返回明确的「功能待接入」状态，待 RAG / LLM 能力接入后填充。
- **聚合大屏快照策略**：驾驶舱 / 图谱 / 归因 / 报告等重聚合端点暂以「快照表 `view_snapshots`」承载（数据来自 `mock_data.json`），保证契约形状不变；后续各 Sprint 用查询服务（SQL 聚合 / 物化视图）替换，**接口形状不变**。

### 1.1 技术栈

| 层 | 选型 | 说明 |
| --- | --- | --- |
| Web 框架 | FastAPI 0.110+ | 异步、自动 OpenAPI、类型校验 |
| ORM | SQLAlchemy 2.0 | 声明式模型 + `Session` |
| 迁移 | Alembic 1.13+ | 关系表版本管理 |
| 数据库 | SQLite（本地）/ PostgreSQL 16（生产） | `DATABASE_URL` 环境变量切换 |
| 鉴权 | PyJWT（HS256） | `Bearer` Token，依赖 `get_current_user` |
| 容器 | Docker / docker-compose | Postgres 16 + Redis 7 + backend |

├── scripts/export_openapi.py# 导出 openapi.json（59 个 path）

├── Dockerfile / docker-compose.yml / .dockerignore

**分层原则**：
- **Router（薄）**：仅做请求参数解析、`get_current_user` 依赖注入、调用 `repo.*`、把返回值包进 `ok()`。复杂业务逻辑一律下沉到 `repo`。
- **Repo（厚）**：所有 SQL、聚合、写操作、字段映射（把数据库列名映射成前端契约字段名）。
- **聚合大屏**：仍由 `seed(key)` 从 `view_snapshots` 表读取，router 直接 `ok(seed(key))`。

## 3. 统一响应信封与鉴权

### 3.1 信封

所有接口返回统一结构（`core/envelope.Envelope`）：

```json
{ "code": 0, "message": "success", "data": { }, "traceId": "..." }
```

- `code == 0` 表示业务成功；非 0 为业务失败（`BizError`）。
- `HTTPException`（401/404/422…）被 `main.py` 异常处理器包成同一信封（`code` 取 HTTP 状态码），前端统一 `if (res.code !== 0) throw`。
- 业务逻辑异常用 `BizError(code, message)` 抛出。

### 3.2 鉴权

- `POST /auth/login {username, password, role}` → 签发 `Bearer` JWT，返回 `{token, user}`。
- `authenticate()` 优先查真实 `users` 表（`get_user_by_username`），表为空或异常时回退内置演示账号 `student/123456`、`teacher/123456`，保证本地零配置可跑。
- 受保护端点通过 `Depends(get_current_user)` 注入 `UserClaims(user_id, role)`；缺失/失效令牌 → 401。

## 6. 练习闭环（核心真实逻辑）

`repo.submit_answer` 与 `repo.finish_session` 构成完整学习闭环：

1. **组卷** `create_practice_session`：按 `mode` 选知识点（weak 模式取掌握度 < 70 的知识点），从 `questions` 表抽取题目，写入 `practice_sessions`。
2. **判分** `submit_answer`：与 `questions.answer` 比对（大小写归一）→ `correct`；写入 `submissions`（含 `duration`）。
3. **掌握度更新（EMA）**：`mastery = prev*0.7 + (100 if correct else 0)*0.3`；若该知识点掌握度 < 60，自动写入黄色 `lowMastery` 预警。
4. **报告** `finish_session`：统计本次会话正确率、班级近似正确率、各知识点前后掌握度变化（`kpChanges`）、错误类型分布、能力增益（`scoreGain`）、下一步建议（`nextSuggestion`）。前端报告页按此形状渲染图表。
5. **错题本** `wrong_book`：所有 `correct=False` 的 `submissions` 即错题；`mastered=True`（标记已掌握）后移出待攻克列表。

> 前端在 submit/finish 时固定传 `sessionId:'cur'`（忽略 create 返回的真实 id）。后端用进程内 `_current[student_id]` 记录「当前会话」并解析，保证判分与报告关联到真实组卷。

## 7. AI 模块暂缓说明

- `POST /ai/chat` 返回：
  ```json
  { "available": false,
    "reason": "AI 答疑功能暂缓上线，后期接入（RAG 检索 + 严格溯源）。" }
  ```
- `POST /question/gen` 返回类似结构（`available:false`）。
- 路由、鉴权、请求/响应信封均保留，前端据此展示「功能待接入」入口，不影响其余功能。
- 后期接入：RAG 检索（教材/课件/视频切片 + 向量库）+ LLM 结构化生成（带 `kpPath/preKp/postKp/sourceRef` 溯源回填），替换占位即可，**不改前端**。

## 8. 开发流程（落地步骤）

1. **契约先行**：以 `docs/接口文档.md` 与 `mock_data.json` 为唯一契约，确定每个端点的请求/响应形状与 `API_PREFIX=/api/v1`、统一信封。
2. **数据建模**：把前端实体落成关系表（`models.py`），聚合大屏用 `view_snapshots` 快照承载。
3. **种子层**：`seed.ensure_db()` 首次启动建表 + 从 `mock_data.json` 灌种；保留 `seed(key)` 供聚合端点读取。
4. **Repo 层**：实现所有真实读写与聚合（`repo.py`），函数签名稳定，供路由调用。
5. **路由层**：逐个 router 改为调用 `repo.*`（实体端点）或 `seed(key)`（聚合端点），并做字段名映射以对齐前端。
6. **AI 暂停**：保留 `/ai/chat`、`/question/gen` 路由，返回 `available:false`。
7. **契约测试门禁**：`tests/contract_check.py` 用 `TestClient` 真实调用全部受保护端点，断言信封 + 关键形状，作为 CI 闸门（当前 47/47 通过）。
8. **容器化 & OpenAPI**：`Dockerfile`/`docker-compose.yml` 一键起 Postgres + backend；`scripts/export_openapi.py` 导出 `openapi.json` 供前端/联调使用。
9. **多人协作**：按 `student.js`/`teacher.js` 拆分为学生端、教师端、练习、题库、图谱、干预等子模块，每人负责若干 router + 对应 repo 函数。

## 9. 本地运行

```bash
cd course-agent/backend
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

# 默认 SQLite（自动建库 course_agent.db）
uvicorn app.main:app --reload --port 8000

# 或连 Postgres
# DATABASE_URL=postgresql+psycopg://user:pass@localhost:5432/course_agent uvicorn app.main:app --reload --port 8000
```

启动后访问 `http://localhost:8000/health` 与 `http://localhost:8000/docs`（Swagger）。

### 9.1 前端对接（零改页面）

把 `assets/js/api.js` 顶部 `config.mode` 改为 `'http'`，并确保请求路径前缀 `/api/v1` 与后端 `API_PREFIX` 一致（通过 Nginx/Vite 反代 `/api` → `:8000`，或开发期开启 CORS）。登录后 `token` 由后端签发。

## 10. 契约测试门禁

```bash
cd course-agent/backend
python tests/contract_check.py
```

覆盖：未鉴权 401、登录拿 token、全部受保护 GET 信封 `code==0` 且含 `data`、关键端点 `data` 顶层键 ⊇ `mock_data.json`、POST 最小逻辑（判分返回 `correct`、AI 返回 `available:false`）。任一失败退出码非 0。

### 实时 HTTP 冒烟（独立于 TestClient）

`tests/contract_check.py` 走 `TestClient`（进程内），而 `tests/live_smoke.py` 对**真实运行的 uvicorn 服务**发 HTTP 请求，覆盖契约测试未触及的端点（改密、审核、干预确认、AI 暂缓态、知识点详情、教师热力图等）。两步：

```bash
# 终端 1：启动真实服务
python -m uvicorn app.main:app --host 127.0.0.1 --port 8011
# 终端 2：跑实时冒烟（可用 BASE_URL 环境变量覆盖地址）
python tests/live_smoke.py
```

当前结果：契约测试 47/47 通过；实时 HTTP 冒烟 17/17 通过（含未鉴权 401 与 AI `available:false`）。
